# 设计草案（v0.1）

## 目标（M1 · 网易云）

一个本地搜索服务：把**我的网易云数据 + 搜索命中的全部条目**收进本地索引，按自定义规则排序，一屏看全所有版本。

## 架构（草案）

    [采集器 collectors] → [本地索引 index] → [搜索服务 api] → [前端 web]
      网易云接口族           SQLite FTS5          FastAPI          简单网页
      （多入口聚合）

## 采集器（collectors）

入口不止"搜索"，而是把所有能拿到数据的入口都聚合起来：

- 单曲搜索 search/get/web + cloudsearch（**分页扫穿**，取全量）
- 专辑搜索 / 歌手搜索 / 歌词搜索
- 歌手页：热歌全量（api/artist/{id}）
- 专辑页：全曲目（api/album/{id}）
- 歌单：用户歌单全量（含私有的公开分享链接）
- 歌曲详情 / 版权状态（api/song/detail、song/enhance/player/url）

要点：单次搜索必须"分页扫穿 + 多入口合并"——这才能把官方藏起来的条目捞回来（实测案例：原唱在搜索结果第 227 位，不扫穿根本见不到）。

## 索引（index）

- SQLite FTS5 + jieba 分词（中文标题切词；日文/英文以 n-gram 兜底）。
- 表：`songs` / `artists` / `albums` / `versions` / `sources`；`versions` 关联同一首歌的多版本（原唱/伴奏/翻唱/不同专辑）。
- 记录来源批次与时间戳，支持增量更新。

## 排序（ranking）

自定义评分（**不透传平台排序**）：

1. 标题精确匹配 > 前缀匹配 > 分词匹配；
2. 目标艺人原版 > 官方版本（伴奏 / solo / acoustic）> 翻唱；
3. 同分内部参考平台热度（温和权重，不主导）；
4. 全部版本并列展示，不折叠、不插入推广。

## 验收（M1）

- [ ] 搜「キラキラだとか夢だとか」：3 个原唱版本全部出现在一屏内；
- [ ] 搜歌单内任意条目：必定命中（歌单已全量入库）；
- [ ] 对照测试集（含官方埋没案例、正常案例）全部通过。

## 风险与边界

- 抓取限速、礼貌访问（页面间 sleep，不与平台对抗）；
- 数据仅本地个人使用；开源仓库不含抓取数据；
- 平台接口随时会变，采集器设计为可替换模块；
- 未来若公开分发，注意平台服务条款与版权合规。
