# 档案与下架侦测（B15 · v0.4.5 第一步）

## 为什么做

B站视频会被下架或转为「不可见」，但平台搜索不会告诉你「上次看到的那个视频没了」。
这个模块把**见过的视频**记成本地档案，复查时逐条验活，先把「哪些视频被下架了」看得到。

## 做了什么（v0.4.5）

- 每次 B站搜索（视频系四个维度）把**通过治理**的条目写进本地档案：
  `data/archive.sqlite3`（gitignore，不入仓）。
- 档案字段：`bvid / 标题 / UP主 / mid / 封面 / 发布时间 / 播放 / 弹幕 / 首见时间 / 末见时间 / 状态 / 复查时间 / 平台错误码`
- 复查：`GET /api/archive/recheck?limit=10`
  逐条调用 `x/web-interface/view`（间隔 0.8 秒，礼貌访问），判定：
  - `ok`（code 0）
  - `gone`（-404 稿件不存在）
  - `hidden`（-403 稿件不可见/权限限制）
  - `error`（其他；如 bvid 非法 -400）
- 查询：`GET /api/archive?q=&status=&limit=50`——`gone/hidden` 排最前，其余按末见时间倒序
- 统计：`GET /api/archive?limit=0` → `stats{total, ok, gone, hidden, error, unknown, last_check}`
- UI：B站页签 →「档案 · 下架侦测」折叠面板：本地档案数 / 已下架 / 不可见 / 上次复查；
  「复查最近 10 个」「已下架列表」两个按钮。

## 边界

- **只存元数据，不存视频内容**；档案只在本地，不进仓库。
- 复查只问状态，不下载任何内容。
- 「换源前的视频回看」「下架视频回看」是后续版本（需要本地快照或镜像源），另立条目。
- 复查只在用户点按钮时发生——不会后台自动抓取。

## 命令行复查（ARCH-2 · 2026-10-22）

`tools/recheck_archive.py`：默认 dry-run（`mode=ro` 只读、不写库），`--apply` 才写回；
`--order last_seen` 用来找长期没被再搜到的旧档（更容易捞到下架）；`--apply-db` 可先写副本。
50 条实测分布与用法见 `docs/ARCH2_RECHECK_TOOL.md`。

## 注意

- 档案随搜索增长，目前没有清理策略（与 E4 一起处理）。
- 判定为 `error` 的不算下架（可能是接口风控或 bvid 格式问题），复查会一直重试。
- 实测缺口：code `62002`（稿件不可见）目前落在 `error` 而非 `hidden`，后续修 `video_status` 映射。
